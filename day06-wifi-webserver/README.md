# Day 06 — 连 WiFi + 内建网页服务器，手机/电脑控制彩灯

日期：2026-10-31
工程：`D:\100-days-embedded\day06-wifi-webserver`
硬件：ESP32-S3-N16R8（DevKitC-1 型），板载 WS2812 接 GPIO48

## 目标现象

板子连上路由器 → 串口打印一个 IP → 手机或电脑浏览器打开这个 IP →
出现 6 个颜色按钮 + 呼吸开关 + 熄灭，点一下灯立刻响应。

本次实测地址：**http://10.2.139.130**（你的可能不同，以串口打印为准）

## 怎么复现

```powershell
cd D:\100-days-embedded\day06-wifi-webserver
pio run              # 编译（第一次约 60 秒）
pio run -t upload    # 烧录（约 15 秒，烧录前先关串口监视器）
pio device monitor   # 115200，按 RST
```

串口正常输出：

```
Day 6: WiFi + WebServer
AP ready -> http://192.168.4.1
connecting to geely
.....
WiFi connected!
>>> 用这个地址访问: http://10.2.139.130
HTTP server started
status: AP设备数=0, 累计访问=0, STA=10.2.139.130
```

最后那行 `status` 每 5 秒刷一次：`AP设备数` = 有几个设备连着板子自己发的热点，
`累计访问` = 网页被打开过几次。**排查"连不上"时先看这两个数**。

也可以双击 `flash_day6.bat` 一键烧（不用管 VS Code 打开的是哪个工程）。

## 今天学到的（重点看这段）

### 1. 网页控制的本质就是"点链接"

每个按钮其实是一个网址：

| 链接 | 作用 |
|---|---|
| `/color?i=0..5` | 切换颜色 |
| `/breath?on=1` / `=0` | 开/关呼吸 |
| `/off` | 熄灭 |

板子收到请求 → 改灯的状态 → 回一个 303 跳回首页。
智能家居、路由器后台，全是这个套路。

### 2. `loop()` 里必须有 `server.handleClient()`

它负责"接待"请求。呼吸灯也在同一个 `loop()` 里跑 —— Day 5 那套
`millis()` 非阻塞思路再次生效：WiFi 和呼吸互不耽误。

### 3. 最大的坑：没外网的热点，设备不愿意待在上面（今天卡最久的地方）

板子自己发的热点（`ESP32-S3` / `192.168.4.1`）**没有互联网**，结果：

- Windows 连上后几秒就自动跳回原来的 WiFi（实测：拿到 192.168.4.2 又被拉回 geely）
- 安卓手机同理，会提示"此网络无法上网"并偷偷走 4G

所以最后改成 **STA 模式连路由器**：板子和手机、电脑在同一个有外网的网络里，
大家才都待得住。**这也是真实物联网设备的做法** —— 设备连你家路由器，
AP 热点只在"首次配网"时才用。

### 4. 另一个坑：手机开热点时，它自己连不了别的 WiFi

之前反复失败的原因之一：手机是 `Redmi K70` 热点的发射源，它不能同时作为
客户端去连接板子的热点，所以 `AP设备数` 永远是 0。

### 5. ESP32 只支持 2.4GHz

5G 频段、需要网页认证的校园网，都连不上。串口会打印 `路由器没连上`。

### 6. WiFi 密码不要写进代码（会被推到公开 GitHub）

密码单独放在 `include/wifi_secrets.h`，`.gitignore` 里加了 `**/wifi_secrets.h`，
所以这个文件不会被提交。模板见 `include/wifi_secrets.example.h` ——
换电脑后复制成 `wifi_secrets.h` 再填自己的密码即可。

> 注意：最早那版把 `Redmi K70` 的明文密码写进了 `main.cpp`，
> 如果不放心可以去改一下那个热点的密码。
